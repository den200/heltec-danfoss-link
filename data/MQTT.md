- Built-in ESP MQTT client; low-priority network task on core 0, bounded inbound
  command queue (8), latest-only snapshot queue (1), capped outbound backlog.
  Radio still runs at high priority on core 1 without network calls.
- Spare node 15 only. MQTT cannot enable control, change autostart or release SHADOW.
  Commands to disabled nodes are rejected. No MQTT control test with CC powered on.
- Clean MQTT sessions; retained command replays, DUP frames, fragmented commands,
  invalid temperatures and stale/disconnected-epoch requests are rejected. The HA
  command topic is danfoss/ffd2bb2d/head/15/set, plain 4–28 C in half-degree steps.
- Queued versus accepted target published separately. Accepted is a local/CC
  observation or link-delivered target, never proof of physical valve position or
  displayed application. No unverified room temperature or valve percentage.
- New local actions cancel older pending targets. Commands received before a newer
  local action are rejected even if console processing was delayed. This corrects
  0.6's pending-command exception to local precedence; hardware retest required.
- HA climate discovery, bridge LWT availability and per-head availability. In SHADOW
  the climate is unavailable, and recovered targets are marked with unknown age
  until a fresh authenticated head report. Diagnostics carry request/pending age.
- First version uses authenticated MQTT over the local LAN (port 1883); TLS and
  runtime Wi-Fi/network provisioning are not implemented. Private build header
  generated by tools/configure_bridge_network.py; no header means networking off.
